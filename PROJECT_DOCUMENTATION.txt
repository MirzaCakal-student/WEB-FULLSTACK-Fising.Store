FILE: AdminService.js
PURPOSE: Manages the admin panel functionality for managing products, users, orders, and payments
LOCATION: FRONTEND/JS/AdminService.js

FUNCTIONS:

1. init()
   - Initializes the admin panel
   - Checks if the current user has admin role (Constants.ADMIN_ROLE)
   - If not admin, shows error toast and redirects to #home
   - Loads all data: products, users, orders, and payments
   - Sets up event handlers

2. setupEventHandlers()
   - Attaches submit event handlers to product and user forms
   - Prevents default form submission and calls appropriate save methods

3. loadProducts()
   - Makes GET request to 'products' endpoint via RestClient
   - On success, calls renderProductsTable() with the product data

4. renderProductsTable(products)
   - Takes array of products as parameter
   - Generates HTML table rows for each product
   - Displays: product ID, image, name, category, price, stock quantity
   - Includes Edit and Delete buttons for each product
   - Uses Utils.getImageUrl() to format image URLs properly
   - Adds onerror handler to show placeholder if image fails to load

5. openAddProductModal()
   - Clears all form fields in the product modal
   - Sets modal title to "Add Product"
   - Sets default category to "Rods"
   - Shows the Bootstrap modal

6. editProduct(productId)
   - Makes GET request to get product by ID
   - Populates the product form with existing product data
   - Changes modal title to "Edit Product"
   - Shows the Bootstrap modal

7. saveProduct()
   - Collects form data (name, category, price, stock, image URL)
   - Validates that required fields are filled
   - If product_id exists: makes PUT request to update product
   - If no product_id: makes POST request to create new product
   - Shows success/error toast messages
   - Closes modal and reloads product list on success

8. deleteProduct(productId)
   - Shows confirmation dialog
   - Makes DELETE request to remove product
   - Reloads product list on success

9. loadUsers()
   - Makes GET request to 'users' endpoint
   - Calls renderUsersTable() with user data

10. renderUsersTable(users)
    - Generates HTML table rows for each user
    - Displays: user ID, username, email, role badge, created date
    - Role badge is red for admin, blue for regular user
    - Includes Edit and Delete buttons

11. openAddUserModal()
    - Clears all form fields in user modal
    - Sets modal title to "Add User"
    - Sets default role to "user"
    - Shows the Bootstrap modal

12. editUser(userId)
    - Gets user data by ID via RestClient
    - Populates user form with existing data
    - Password field left empty (not showing existing password)
    - Shows the modal

13. saveUser()
    - Collects form data (username, email, role, optional password)
    - Validates required fields
    - For updates: makes PUT request (password optional)
    - For new users: validates password is provided, then makes POST request
    - Shows success/error messages
    - Reloads user list on success

14. deleteUser(userId)
    - Shows confirmation dialog
    - Makes DELETE request
    - Reloads user list on success

15. loadOrders()
    - Makes GET request to 'orders' endpoint
    - Calls renderOrdersTable() with order data

16. renderOrdersTable(orders)
    - Generates table rows for each order
    - Displays: order ID, user ID, total amount, payment status, created date
    - Includes View button for each order
    - If no orders, shows "No orders yet" message

17. viewOrder(orderId)
    - Placeholder function showing "coming soon" toast
    - Intended for viewing order details in future

18. loadPayments()
    - Makes GET request to 'payments' endpoint
    - Calls renderPaymentsTable() with payment data

19. renderPaymentsTable(payments)
    - Generates table rows for each payment
    - Displays: payment ID, order ID, amount, payment method, status, created date
    - If no payments, shows "No payments yet" message

CODE EXPLANATION:
- Uses jQuery for DOM manipulation and event handling
- All API calls go through RestClient for consistent authentication
- Uses Bootstrap modals for add/edit interfaces
- Utils.blockUI() and Utils.unblockUI() provide loading indicators
- Utils.showToast() displays user feedback messages
- Image handling includes fallback placeholders for missing images

FILE: AuthService.js
PURPOSE: Handles user authentication (login, logout, registration)
LOCATION: FRONTEND/JS/AuthService.js

FUNCTIONS:

1. init()
   - Initializes authentication state when page loads
   - Checks localStorage for existing user_token and user data
   - If token exists, parses user data and updates navbar
   - Loads cart and wishlist counts if user is logged in
   - If token/user is invalid, logs out user
   - Sets up form submission handlers for login and signup forms

2. handleLogin(form)
   - Extracts email and password from login form
   - Validates that both fields are filled
   - Makes POST request to "auth/login" endpoint with credentials
   - On success: stores token and user data in localStorage
   - Logs authentication details to console for debugging
   - Updates navbar to show logged-in state
   - Shows success toast and redirects to home page
   - On error: displays error message via toast

3. handleSignup(form)
   - Extracts name, surname, email, and password from signup form
   - Combines first and last name into single username field
   - Validates all required fields are filled
   - Makes POST request to "auth/register" endpoint
   - On success: auto-logs in the user by storing token and user data
   - Updates navbar and redirects to home
   - On error: displays error message

4. logout(askConfirmation = true)
   - Optionally shows confirmation dialog
   - Removes user_token and user from localStorage
   - Updates navbar to logged-out state
   - Resets cart and wishlist badge counts to 0
   - Shows logout success message
   - Redirects to home page

5. isLoggedIn()
   - Checks if both user_token and user exist in localStorage
   - Returns boolean true/false

6. getCurrentUser()
   - Retrieves user string from localStorage
   - Parses JSON to get user object
   - Returns user object or null if parsing fails

CODE EXPLANATION:
- Uses localStorage for client-side session persistence
- JWT tokens are stored in "user_token" key
- User object is stored as JSON string in "user" key
- All AJAX calls use jQuery's $.ajax() with JSON content type
- Token is included in Authorization header for protected routes
- Form handlers use $(document).off().on() to prevent duplicate event bindings

FILE: CartService.js
PURPOSE: Manages shopping cart functionality
LOCATION: FRONTEND/JS/CartService.js

PROPERTIES:
- cartItems: Array storing current cart items

FUNCTIONS:

1. init()
   - Initializes cart service
   - Calls loadCart() to fetch cart data from backend

2. loadCartCount()
   - Checks if user is logged in via AuthService
   - If not logged in, sets badge count to 0
   - Makes GET request to 'cart' endpoint
   - Updates cart badge with item count

3. loadCart()
   - If user not logged in, shows empty cart message
   - Makes GET request to fetch full cart with product details
   - Stores cart items in cartItems property
   - Calls renderCart() to display items
   - Updates cart count badge

4. addItem(productId, quantity = 1)
   - Checks if user is logged in (redirects to login if not)
   - Makes POST request to 'cart' endpoint with product_id and quantity
   - Shows success toast message
   - Updates cart count badge

5. updateQuantity(cartItemId, newQuantity)
   - If quantity < 1, calls removeItem() instead
   - Makes PUT request to update cart item quantity
   - Reloads full cart to reflect changes

6. removeItem(cartItemId)
   - Shows confirmation dialog
   - Makes DELETE request to remove specific cart item
   - Reloads cart after removal

7. clearCart()
   - Shows confirmation dialog
   - Makes DELETE request to 'cart' endpoint (clears entire cart)
   - Reloads cart to show empty state

8. renderCart()
   - Checks if user is logged in and cart has items
   - If empty, shows/hides appropriate div elements
   - For each cart item, generates HTML row with:
     - Product image with fallback placeholder
     - Product name and unit price
     - Quantity controls (-, input, + buttons)
     - Item total (price × quantity)
     - Delete button
   - Calculates subtotal by summing all item totals
   - Updates subtotal and final total displays

9. renderEmptyCart()
   - Hides cart content container
   - Shows empty cart message div

CODE EXPLANATION:
- Cart is user-specific and stored in backend database
- Each cart item has: cart_item_id, user_id, product_id, quantity, price, name, image_url
- Quantity can be updated with +/- buttons
- Real-time price calculations (quantity × unit price)
- Utils.blockUI() shows loading state during operations
- All operations require authentication (checked via AuthService)

FILE: CheckoutService.js
PURPOSE: Handles multi-step checkout process
LOCATION: FRONTEND/JS/CheckoutService.js

PROPERTIES:
- currentStep: Tracks which step user is on (1-4)
- checkoutData: Object storing:
  - personalInfo: {firstName, lastName, email, phone}
  - shippingInfo: {country, city, address, zip}
  - cartItems: Array of items being purchased
  - totalAmount: Total price including shipping

FUNCTIONS:

1. init()
   - Initializes checkout process
   - Checks if user is logged in (redirects if not)
   - Loads cart items for checkout
   - Pre-fills personal info from logged-in user
   - Sets up all event listeners
   - Shows step 1 by default

2. setupEventListeners()
   - Attaches handlers to personal info form submission
   - Attaches handlers to shipping address form submission
   - Sets up Next button clicks (data-next attribute)
   - Sets up Back button clicks (data-back attribute)
   - Attaches handler to final "Finish Order" button

3. loadCartForCheckout()
   - Makes GET request to 'cart' endpoint
   - Stores cart items in checkoutData.cartItems
   - Calls calculateTotal() to compute order total

4. calculateTotal()
   - Loops through cart items
   - Multiplies price × quantity for each item
   - Sums up to get total amount
   - Stores in checkoutData.totalAmount

5. prefillPersonalInfo()
   - Gets current user from AuthService
   - Pre-fills email field with user's email
   - Splits username into first and last name
   - Pre-fills first name and last name fields

6. goToStep(step)
   - Validates current step before proceeding
   - If validation fails, stays on current step
   - Saves current step data
   - Calls showStep() to display target step

7. showStep(step)
   - Updates currentStep property
   - Hides all step divs by removing 'active' class
   - Shows target step div by adding 'active' class
   - Updates progress circle indicators
   - If showing step 3 (review), calls populateReview()

8. validateStep(step)
   - For step 1: calls validatePersonalInfo()
   - For step 2: calls validateShippingInfo()
   - For steps 3 & 4: returns true (no validation)

9. validatePersonalInfo()
   - Checks firstName, lastName, email, phone are filled
   - Validates email format using regex
   - Verifies email matches logged-in user's registered email
   - Adds/removes Bootstrap validation classes (is-invalid, is-valid)
   - Shows toast messages for validation errors

10. validateShippingInfo()
    - Validates country, city, address, zip are filled
    - Adds/removes validation classes
    - Returns boolean result

11. saveStepData(step)
    - For step 1: saves personal info to checkoutData
    - For step 2: saves shipping info to checkoutData

12. populateReview()
    - Generates HTML table rows for all cart items
    - Shows product image, name, price, quantity
    - Includes +/- buttons to adjust quantity in review step
    - Calculates subtotal, adds shipping cost (€5.00)
    - Displays all totals
    - Shows personal info summary (name, email, phone)
    - Shows shipping address summary
    - Updates both step 3 and step 4 total displays

13. updateCartQty(cartItemId, newQty)
    - If quantity < 1, calls removeCartItem()
    - Makes PUT request to update cart item
    - Reloads cart and refreshes review display

14. removeCartItem(cartItemId)
    - Shows confirmation dialog
    - Makes DELETE request to remove item
    - Reloads cart and refreshes review

15. processPayment()
    - Gets current user and selected payment method
    - Validates cart is not empty
    - Prepares checkout data object with all info
    - Makes POST request to 'checkout' endpoint
    - On success:
      - Shows success modal with order ID
      - Displays confirmation email address
      - Shows success toast
    - On error: displays error message

16. finishCheckout()
    - Clears checkoutData object
    - Resets to step 1
    - Hides success modal
    - Redirects to home page
    - Shows thank you toast

17. isValidEmail(email)
    - Uses regex to validate email format
    - Returns boolean

CODE EXPLANATION:
- Multi-step wizard: Personal Info → Shipping → Review → Payment
- Each step has validation before proceeding
- Data is saved incrementally as user progresses
- Review step allows editing quantities before final submission
- Checkout process creates order, order items, payment, and address records
- Cart is cleared after successful checkout
- Email must match registered user's email (security measure)
- Shipping cost is hardcoded to €5.00

FILE: ProductService.js
PURPOSE: Manages product listing, filtering, sorting, and cart operations
LOCATION: FRONTEND/JS/ProductService.js

PROPERTIES:
- allProducts: Array of all products loaded from backend
- filteredProducts: Array of products after applying search/filter

FUNCTIONS:

1. init()
   - Initializes product service
   - Calls loadProducts() to fetch all products
   - Sets up event handlers for search, filter, and sort

2. setupEventHandlers()
   - Attaches input event to search field (#prod-search)
   - Attaches change event to category dropdown (#prod-category)
   - Attaches change event to sort dropdown (#prod-sort)
   - All trigger filterProducts() or sortProducts() appropriately

3. loadProducts()
   - Makes GET request to 'products' endpoint
   - Stores data in allProducts array
   - Copies to filteredProducts array
   - Calls renderProducts() to display
   - On error: shows error alert in products container

4. filterProducts()
   - Gets search term from search input (lowercase)
   - Gets selected category from dropdown
   - Filters allProducts array where:
     - Product name or category includes search term
     - Product category matches selected category (or "all")
   - Updates filteredProducts array
   - Calls sortProducts() to apply sorting

5. sortProducts()
   - Gets sort option from dropdown (name-asc, name-desc, price-asc, price-desc)
   - Sorts filteredProducts array using array.sort()
   - For name: uses localeCompare()
   - For price: uses parseFloat() and subtraction
   - Calls renderProducts() to update display

6. renderProducts()
   - Updates product count display
   - If no products match filters, shows "empty" message
   - For each product, generates card HTML with:
     - Product image with click-to-zoom functionality
     - Wishlist heart button (if logged in)
     - "In Stock" badge (if stock > 0)
     - Category label
     - Product name and price
     - Stock availability text
     - Quantity selector (+/- buttons)
     - "Add to Cart" button (or "Out of Stock" if unavailable)
   - Wishlist button shows filled heart if product is in wishlist
   - Quantity selector is readonly input with min/max validation

7. changeQty(productId, delta)
   - Finds quantity input for specific product
   - Gets current value and max stock
   - Adds delta (-1 or +1)
   - Enforces bounds (min=1, max=stock_quantity)
   - Updates input value

8. addToCart(productId)
   - Checks if user is logged in (redirects if not)
   - Gets quantity from input field
   - Calls CartService.addItem() with product ID and quantity

9. openImageModal(imageUrl, productName)
   - Creates Bootstrap modal instance
   - Sets modal image src and alt attributes
   - Shows modal for full-size product image view

CODE EXPLANATION:
- Products can be filtered by search term and category
- Sorting options: alphabetical (A-Z, Z-A) and price (low-high, high-low)
- Each product card shows real-time stock availability
- Quantity selector prevents ordering more than available stock
- Wishlist functionality integrated (toggle heart icon)
- Click on product image to view full-size
- "Add to Cart" button disabled for out-of-stock items
- Uses Utils.getImageUrl() and getPlaceholderImage() for image handling

FILE: UserService.js
PURPOSE: Manages user profile editing, password changes, and account deletion
LOCATION: FRONTEND/JS/UserService.js

PROPERTIES:
- currentUser: Stores the logged-in user object

FUNCTIONS:

1. init()
   - Calls loadProfile() to populate form
   - Initializes profile form handler
   - Initializes password change form handler
   - Sets up email availability checker
   - Initializes password strength meter

2. loadProfile()
   - Gets current user from Utils.getCurrentUser()
   - If no user, redirects to login page
   - Splits username into first and last name
   - Populates form fields with user data
   - Updates profile header with username and email
   - Updates session info display (email, role badge)

3. initProfileForm()
   - Attaches submit handler to profile form
   - Calls updateProfile() on form submission

4. initPasswordForm()
   - Attaches submit handler to password change form
   - Calls changePassword() on form submission

5. initEmailCheck()
   - Sets up debounced email availability checker
   - On email input, waits 500ms after typing stops
   - If email is same as current, marks as valid
   - If email format is invalid, does nothing
   - Otherwise, calls checkEmailAvailability()

6. checkEmailAvailability(email)
   - Makes GET request to fetch all users
   - Checks if any other user has this email
   - Shows "Email already taken" or "Email available" message
   - Adds Bootstrap validation classes

7. updatePasswordStrength(password)
   - Calculates password strength score (0-100)
   - Checks for: length ≥6, length ≥10, lowercase, uppercase, numbers, symbols
   - Assigns strength level: None, Weak, Medium, Strong
   - Updates progress bar width and color
   - Updates strength text display

8. updateProfile()
   - Collects firstName, lastName, email from form
   - Validates all fields are filled
   - Makes PUT request to update user
   - On success:
     - Updates localStorage with new user data
     - Shows success toast
     - Reloads profile to reflect changes

9. changePassword()
   - Collects currentPassword, newPassword, confirmPassword
   - Validates all fields are filled
   - Checks new passwords match
   - Validates new password is at least 6 characters
   - First attempts login with current password to verify it
   - If current password correct, makes PUT request to update password
   - On success: clears password fields and resets strength meter
   - On error: shows appropriate error message

10. confirmDeleteAccount()
    - Shows first confirmation dialog
    - Prompts user to enter password for confirmation
    - Calls deleteAccount() with password

11. deleteAccount(password)
    - Shows loading indicator
    - First verifies password by attempting login
    - If password correct, makes DELETE request for user account
    - On success: logs out user and redirects
    - On error: shows error message

CODE EXPLANATION:
- Profile update allows changing username and email
- Email availability is checked in real-time with debouncing
- Password change requires current password verification for security
- Password strength meter provides visual feedback
- Account deletion requires password confirmation
- All operations use $.blockUI() for loading states
- Uses toastr for user feedback messages
- Changes to profile update localStorage immediately

FILE: rest-client.js
PURPOSE: Provides centralized AJAX wrapper for API communication
LOCATION: FRONTEND/JS/rest-client.js

FUNCTIONS:

1. get(url, callback, error_callback)
   - Makes GET request to API endpoint
   - Automatically adds Authorization header with JWT token from localStorage
   - On success: calls callback function with response
   - On error: calls error_callback or shows default error toast

2. request(url, method, data, callback, error_callback)
   - Generic request method for POST, PUT, PATCH, DELETE
   - Sets content-type to application/json
   - Automatically adds Authorization header with JWT token
   - Converts data object to JSON string
   - On success: calls callback with response
   - On error: calls error_callback or shows default error toast

3. post(url, data, callback, error_callback)
   - Wrapper that calls request() with method="POST"

4. put(url, data, callback, error_callback)
   - Wrapper that calls request() with method="PUT"

5. patch(url, data, callback, error_callback)
   - Wrapper that calls request() with method="PATCH"

6. delete(url, data, callback, error_callback)
   - Wrapper that calls request() with method="DELETE"

CODE EXPLANATION:
- Centralizes all HTTP requests to backend API
- Automatically handles JWT token authentication
- Uses jQuery $.ajax() internally
- Prepends Constants.PROJECT_BASE_URL to all URLs
- Authorization header format: "Bearer <token>"
- All data is sent/received as JSON
- Provides consistent error handling across app

FILE: spapp.js
PURPOSE: Single Page Application (SPA) router
LOCATION: FRONTEND/JS/spapp.js

FUNCTIONS:

1. loadPage(page)
   - Hides all sections in #spapp container
   - Shows only the active section by ID
   - Loads HTML content from HTML/{page}.html
   - If page not found, shows error alert
   - After loading, calls initializePageService(page)

2. initializePageService(page)
   - Initializes the appropriate service for each page
   - Switch statement maps pages to services:
     - 'products' → ProductService.init()
     - 'cart' → CartService.init()
     - 'wishlist' → WishlistService.init()
     - 'checkout' → CheckoutService.init()
     - 'user' → UserService.init()
     - 'admin' → AdminService.init()

3. getHash()
   - Gets current URL hash
   - Removes '#' character
   - Defaults to "home" if no hash

Main execution:
- On document ready:
  - Loads initial page based on URL hash
  - Sets up hashchange listener to load pages when hash changes

CODE EXPLANATION:
- Implements client-side routing using URL hash
- Each section is loaded dynamically from HTML folder
- Page transitions don't reload the entire page
- Service initialization happens after HTML is loaded
- Example: #products loads HTML/products.html and calls ProductService.init()
- Allows for bookmark-able URLs (e.g., #cart, #checkout)

FILE: utils.js
PURPOSE: Utility functions used throughout the application
LOCATION: FRONTEND/JS/utils.js

FUNCTIONS:

1. parseJwt(token)
   - Extracts payload from JWT token
   - Splits token by '.' to get middle part (payload)
   - Decodes base64 payload
   - Parses JSON and returns payload object
   - Returns null if token is invalid

2. getImageUrl(imageUrl)
   - Formats image URLs for consistent display
   - If no imageUrl, returns placeholder SVG
   - If full URL (http/https/data), returns as-is
   - If starts with 'assets/', prepends FRONTEND base path
   - If just filename, assumes it's in FRONTEND/assets/products/
   - Returns properly formatted full URL

3. getPlaceholderImage()
   - Returns data URI for placeholder image
   - SVG with gray background and "No Image" text

FILE: AuthMiddleware.php
PURPOSE: JWT authentication and authorization middleware
LOCATION: BACKEND/rest/MIDDLEWARE/AuthMiddleware.php

FUNCTIONS:

1. verifyToken()
   - Gets JWT token from 'Authentication' header using Flight::request()->getHeader()
   - If no token, halts with 401 error
   - Decodes JWT using Firebase\JWT library
   - Uses Config::JWT_SECRET() as secret key
   - Algorithm: HS256
   - Stores decoded user object in Flight::set('user', $decoded->user)
   - Stores token in Flight::set('jwt_token', $token)
   - Returns TRUE on success
   - Halts with 401 if token is invalid or expired

2. authorizeRole($requiredRole)
   - Gets authenticated user from Flight::get('user')
   - If no user, halts with 401 (not authenticated)
   - Checks if user's role matches required role
   - If role doesn't match, halts with 403 (forbidden)
   - Returns TRUE if authorized

3. authorizeRoles($roles)
   - Similar to authorizeRole but accepts array of allowed roles
   - Checks if user's role is in the allowed roles array
   - Returns TRUE if user has any of the allowed roles
   - Halts with 403 if user doesn't have required role

4. authorizeOwner($resourceUserId)
   - Checks if user is accessing their own resource
   - Admin role can access any resource (returns TRUE)
   - Regular users can only access resources where user_id matches
   - Halts with 403 if user tries to access another user's resource
   - Returns TRUE if authorized

CODE EXPLANATION:
- Middleware layer between routes and services
- JWT token must be in 'Authentication' header
- Token payload contains user object with user_id, email, role
- Three authorization levels:
  1. verifyToken() - basic authentication
  2. authorizeRole() - specific role required
  3. authorizeOwner() - owner or admin only
- Uses Flight framework's halt() to stop execution and return error
- Admin users have elevated privileges (can access all resources)

EXTENDS: BaseService

   - Removes plain password from entity
   - Sets default role to 'user' if not specified
   - Inserts user into database via $dao->insert()
   - Fetches newly created user record
   - Removes password_hash from user object (security)
   - Creates JWT payload with user object and expiration

   - Encodes JWT using Firebase\JWT library

   - Gets user by email using get_user_by_email()
   - Verifies password using password_verify()
   - Compares plain text password with stored password_hash
   - If invalid, returns error
   - Removes password_hash from user object
   - Creates JWT payload with user and expiration (48 hours)
   - Encodes JWT token
   - Returns success response with user and token

CODE EXPLANATION:
- Password never stored in plain text
- Uses bcrypt for password hashing
- JWT tokens expire after 48 hours
- Auto-login after registration (returns token immediately)
- Token payload contains full user object
- Token signed with Config::JWT_SECRET()
- Client stores token and sends in Authentication header
- password_hash always removed before sending to client

   - Public route (no authentication required)

   - If successful: returns 200 with success message, user, and token

   - Response includes JWT token for client storage

CODE EXPLANATION:
- Both routes are in /auth group

- Both routes return JWT token on success
- Token allows client to make authenticated requests

FILE: CheckoutRoutes.php
PURPOSE: Handles multi-step checkout process
LOCATION: BACKEND/rest/ROUTES/CheckoutRoutes.php

ROUTES:

1. POST /checkout
   - Processes complete checkout flow
   - Gets current user from Flight::get('user')
   - Validates required fields: email, firstName, lastName, phone, address, city, zip, country, paymentMethod

HELPER FUNCTION:

sendOrderConfirmationEmail($toEmail, $customerName, $orderId, $total, $cartItems)

   - Headers: From noreply@fishingstore.com, Reply-To support@fishingstore.com
   - Logs success/failure to error log
   - Returns boolean indicating if email was sent

CODE EXPLANATION:
- Single endpoint handles entire checkout process
- Transaction includes: address, order, order items, payment, email
- Email must match registered user (prevents checkout with different email)
- Shipping is fixed at €5.00
- Cart items are copied to order items (snapshot of cart)
- Cart cleared after successful order
- Email confirmation sent to customer
- All operations wrapped in try-catch for error handling
- Order status set to 'pending' initially
- Payment status set to 'completed' (simplified payment flow)
